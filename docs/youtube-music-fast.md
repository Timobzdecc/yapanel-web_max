# Быстрый YouTube Music на Станции Макс: исследование

Дата: 11.11.2026. Станция: `yandexstation_2` (YNDX-00053, Android 9, arm64), 6,4 ГБ свободно, root/ADB есть. Панель `yapanel-web_max`, текущий путь — публичный поиск YouTube Music + `yt-dlp` + станционный Android `MediaPlayer`.

## Короткий вывод

Текущая схема **принципиально не может** переключать треки за 1–2 секунды: узкое место — не загрузка файла, а извлечение свежего URL через `yt-dlp` (10–20 с) и блокирующий `MediaPlayer.prepare()` (10–14 с). Предзагрузка URL помогает только если пользователь дослушал трек до конца prefetch.

Быстрый путь, который уже проверен на такой же станции в проекте **MaxWave**: установить **YouTube Music ReVanced Extended + GmsCore** и играть **внутри приложения**, а панелью управлять через `MediaSession`/deeplink. Приложение использует ExoPlayer, собственный кэш/предзагрузку и родной поиск; `yt-dlp` для playback не нужен. Переключение становится операцией плеера, а не сетевым извлечением.

## Что измерено

| Этап | Время |
|---|---|
| Поиск YouTube Music (WEB_REMIX) | ~1 с |
| `yt-dlp --get-url` (без cookies) | ~11–12 с |
| `yt-dlp --dump-single-json` | ~17–20 с |
| `MediaPlayer.prepare()` для googlevideo m4a | ~10–14 с |
| Итог: первый трек | ~21–23 с |
| Итог: next после прогрева | ~14–28 с |

Проверки на станции:

- `--get-url` для `5qZQEq_C3vc` — 11,8 с; `--dump-single-json` — ~20 с.
- Клиенты `tv`, `android_vr`, `web_safari`, `mweb` для `bestaudio[ext=m4a]` не дают форматов; рабочий — default.
- С cookies аккаунта YouTube `yt-dlp` получает **SABR-only** форматы и отвечает `Requested format is not available` для всех аудиоформатов. Без cookies — обычный m4a и успешное воспроизведение. Поэтому cookies используются только для «Моей музыки», не для playback.
- Прямой `youtubei/v1/player` на `music.youtube.com`: `WEB_REMIX` → `UNPLAYABLE`, `ANDROID_MUSIC` → `LOGIN_REQUIRED`, `MWEB` → `UNPLAYABLE`. Быстрого resolver «в один запрос» без PO-токенов/подписи нет.
- `MediaPlayer.prepare()` — блокирующий; это не полная загрузка трека, а буферизация начала HTTP-потока.

## Почему приложение быстрее

YouTube Music ReVanced — это полноценный Android-клиент:

- ExoPlayer с собственным буфером, предзагрузкой и кэшем;
- родной каталог/поиск и очередь YouTube Music;
- вход в Google-аккаунт внутри приложения (без cookies.txt и `yt-dlp`);
- `MediaSession`, через которую можно читать состояние и управлять плеером.

MaxWave (v0.2.0, та же модель/прошивка) делает ровно это:

- каталог запрашивается со станции напрямую через `music.youtube.com/youtubei/v1/search|browse` (таймаут 8 с, обычно ~1 с);
- playback открывается deeplink-ом в `app.rvx.android.apps.youtube.music/com.google.android.apps.youtube.music.activities.MusicActivity`:
  `https://music.youtube.com/watch?v=<videoId>[&list=<playlistId>]`;
- статус и управление — через `MediaSession` пакета YouTube Music:
  `playFromSearch`, `play`, `pause`, `skipToNext`, `skipToPrevious`, `seekTo`, `setRating`;
- голос — Frida-хук в `com.yandex.io.sdk` + локальный классификатор фраз;
- VPN (Happ) ограничен только UID YouTube Music; Алиса и остальное идут напрямую;
- приложение автозапускается и watchdog’ом поднимается после сбоев.

Для нашей панели Frida не обязательна: поиск у нас уже есть, deeplink можно отправить через `am start`, а управление/статус — через `MediaController`/`dumpsys media_session`/media-keys. Голос — через наш локальный ассистент.

## Варианты

| Вариант | Ожидаемое переключение | Плюсы | Минусы |
|---|---:|---|---|
| **A. ReVanced YouTube Music + MediaSession** | 1–2 с | Нативный ExoPlayer, аккаунт, кэш/предзагрузка, статус, голос; проверено MaxWave | Нужно поставить APK + GmsCore, войти в Google; VPN может понадобиться; версия приложения фиксирована |
| B. Свой APK на ExoPlayer/Media3 + PreloadManager | 1–2 с после prefetch | Полный контроль, без ReVanced | Всё равно нужен resolver (10–20 с), много разработки |
| C. Второй подготовленный `MediaPlayer` + prefetch | 1–3 с после prefetch | Без нового APK, небольшой объём | Первый/непрогретый трек всё равно 10–20 с; `MediaPlayer` хуже ExoPlayer |
| D. Быстрый resolver через YouTubei player API | <1 с | Идеально | Сейчас `UNPLAYABLE`/`LOGIN_REQUIRED`; нужны PO-токены/подпись |
| E. Локальный прокси/префетч потока | чуть быстрее | Меньше влияние сети | Не убирает 10–20 с извлечения URL |

Рекомендация: **A** как основной путь, **C** как временный fallback и **D** не тратить время, пока YouTube не отдаёт прямые URL.

## План внедрения A

1. **Пилот на станции**
   - Установить `YouTube-Music-ReVanced-8.12.54.apk` и `GmsCore.apk` из релиза MaxWave v0.2.0 (или собрать свои APK).
   - Войти в Google через scrcpy/пульт, проверить воспроизведение.
   - Сначала без VPN: станция уже открывает YouTube. Если YouTube тормозит/блокирует — Happ, VPN только для UID `app.rvx.android.apps.youtube.music`, без lockdown.
   - Замерить: холодный старт, deeplink на трек, next/prev, seek, pause.

2. **Панель: новый backend `native_yt`**
   - `play(video_id)` → `am start -a android.intent.action.VIEW -d "https://music.youtube.com/watch?v=<id>" -n app.rvx.../MusicActivity`.
   - `status()` → active `MediaSession` YouTube Music: title/artist/state/position/duration; fallback `dumpsys media_session`.
   - `pause/resume/next/prev` → `MediaController.getTransportControls()` (лучше) или `input keyevent 85/87/88/126/127` (проще).
   - `seek` → `MediaController.seekTo` или deeplink с `&t=<sec>s`.
   - `playFromSearch` — опционально: приложение само ищет и играет.
   - Статус отдавать в `/api/music` как `playerType: "external"`, как сейчас для YT.
   - Очередь: для альбома/плейлиста передавать `list=<playlistId>`; для точечного поиска — autoplay приложения (или своя очередь через последовательные deeplink).

3. **Голос**
   - Наш локальный ассистент уже перехватывает фразы; вместо `/api/extmusic/play` вызывать `native_yt` (deeplink/MediaSession).
   - «Пауза/следующий/что играет» — через MediaSession.
   - Frida не нужна для базового сценария; если понадобится перехват системных быстрых команд Алисы — можно взять подход MaxWave.

4. **Fallback и совместимость**
   - Если приложение не установлено/не отвечает — старый `yt-dlp` + `MediaPlayer` (текущий код).
   - VK Music не трогаем.
   - Откат: удалить ReVanced/GmsCore, вернуть `source=yt` на yt-dlp; прошивка/root не меняются.

## Реализовано (11.11.2026)

На станции установлены **YouTube Music ReVanced 8.12.54** и **GmsCore**, приложение запущено и добавлен Google-аккаунт. Playback переведён на нативный ExoPlayer приложения; `yt-dlp` остался fallback'ом на случай, если приложение недоступно.

Что добавлено в панель:

- `extmusic/native_yt.py` — deeplink-запуск трека и клиент нативного контроллера.
- `device/native_yt/NativeMediaCtl.java` + `.dex` — небольшой демон на `app_process`, запускается как root в домене `u:r:shell:s0`. Root проходит проверку `MEDIA_CONTENT_CONTROL`, а shell-домен имеет доступ к `media_session`, поэтому демон отдаёт точные `position/duration/title/artist`, умеет `play/pause/next/prev/stop/seek` и переключает треки без `input keyevent`.
- `extmusic/service.py` — для YouTube сначала пробует нативный путь, при ошибке откатывается на `yt-dlp`; статус, очередь, next/prev, seek, voice и общий плеер работают через нативный путь.
- `static/extmusic.js` — исправлена ошибка: кнопки управления отправляли GET вместо POST, из-за чего pause/next/prev/stop/seek из вкладки «Музыка» не срабатывали. Теперь все control-запросы идут POST.

Замеры на этой станции (YNDX-00053, Android 9):

| Операция | Время |
|---|---:|
| Доставка deeplink `am start` | 0,15–0,4 с |
| Первый трек до звука | 1,4–2,0 с |
| Следующий трек (deep link) | 1,5–2,6 с (в удачном прогретом случае ~0,4 с) |
| Пауза/продолжить через контроллер | 0,1–0,5 с |
| Перемотка `seekTo` | ~1,1 с, позиция точная |
| Старый путь `yt-dlp` + `MediaPlayer` | 20–30 с |

Примечание: deeplink с `&t=60s` в ReVanced **не перематывает** уже играющий трек, а запускает его с начала. Поэтому перемотка сделана через `MediaController.seekTo` в демоне. Очередь панели — это результаты поиска; приложение после трека может включить собственное радио, статус при этом синхронизируется по MediaSession. Если пользователь нажимает next/prev в панели, панель ведёт по своей очереди.

Проверено: поиск и запуск из вкладки «Музыка», следующий/предыдущий, пауза/продолжить, перемотка, общий плеер (`/api/music`), голосовые команды «включи на ютубе …», «следующий», «пауза», «продолжи», «что играет», «стоп».

## Вход в Google из панели

В карточке «Аккаунт YouTube» есть кнопка **«Войти через экран станции»**. Она открывает модальное окно с экраном станции: можно тапать по полям, вводить текст и нажимать системные клавиши. Вход выполняется в WebView GmsCore на станции, пароль не сохраняется и не пишется в логи.

Меры безопасности:

- ввод разрешён только когда на переднем плане `app.revanced.android.gms` (экран входа), иначе API возвращает ошибку и не отправляет нажатия в чужие приложения;
- кнопка «Очистить» стирает предзаполненный Google адрес/телефон;
- после отправки поле в панели очищается;
- панель должна быть в доверенной сети: экран станции виден всем, у кого есть доступ к панели.

Мобильная вёрстка окна исправлена: экран и кнопки не распирают диалог, форма ввода на узком экране складывается в колонку.

## Cookies и «Моя музыка»

`yt-dlp` теперь работает с временной копией cookies и не может перезаписать сохранённый файл анонимными cookies. Панель принимает только файл, в котором есть вход: `SID`, `HSID`, `SSID`, `SAPISID` и т. п. Если cookies протухли, «Моя музыка» покажет понятную ошибку, а не «playlist does not exist».

Для текущего аккаунта плейлист `LM` («Мне нравится» в YouTube Music) пуст, поэтому «Моя музыка» ничего не показывает. Плейлист `LL` («Понравившиеся видео» на YouTube) содержит 137 записей, но это в основном не музыка, поэтому в музыкальную библиотеку они не подмешиваются.

## Плейлисты и миксы

В карточке «Аккаунт YouTube» добавлены кнопки **«Плейлисты»** и **«Миксы»**. Они открывают в том же окне экран станции:

- «Плейлисты» — библиотека приложения: «Понравившаяся музыка», плейлисты, исполнители, альбомы;
- «Миксы» — главная YouTube Music с персональными подборками и настроениями.

Это использует **аккаунт, залогиненный в APK**, поэтому список совпадает с приложением. Тап по плейлисту/миксу запускает его на станции; панель подхватывает текущий трек через MediaSession, а next/prev работают по очереди приложения, пока панельная очередь пуста.

Важно: «Моя музыка» в панели — отдельная cookie-библиотека (`yt-dlp` + cookies из браузера). Она может показывать другой аккаунт или пустой `LM`, даже если в приложении лайкнутые треки есть. Поэтому для реальной библиотеки используйте кнопки «Плейлисты»/«Миксы».

## Вход в YouTube Music

Основной и надёжный способ — **на реальном телевизоре, подключённом к станции по HDMI**, а не формой в панели. Станция отдаёт на ТВ тот же Android-интерфейс, который панель показывает в «экране станции»; CEC на станции включён.

1. Переключи телевизор на HDMI-вход станции.
2. Открой приложение **YouTube Music** на телевизоре.
3. Нажми **«Войти»** (или аватар → добавить аккаунт) и введи Google-аккаунт пультом ТВ (CEC), пультом станции или USB-клавиатурой.
4. Вернись в панель. В карточке библиотеки появится аккаунт, «Понравившаяся музыка», плейлисты и миксы.

Если телевизора под рукой нет, тот же экран можно открыть в панели: **«Библиотека YouTube Music» → «Войти» → экран станции** — и вводить текст из панели.

Выход: кнопка **«Выйти»** в карточке библиотеки удаляет Google-аккаунт из GmsCore и останавливает YouTube Music. После этого вместо «Выйти» показывается **«Войти»**.

Форма **email/пароль** в панели помечена как экспериментальная: Google-WebView не всегда отдаёт поля и может требовать капчу/2FA. Если форма не сработала — используй экран станции (телевизор).

## Риски

- ReVanced/GmsCore — сторонние APK; Google-вход и VPN могут сломаться после обновлений. Версию фиксировать.
- На станции нет Play Store; вход и обновления — вручную/scrcpy.
- `MediaSession`-контроль зависит от версии приложения; `input keyevent` — запасной путь.
- VPN нужен не всегда; если включать — только для YouTube Music, без lockdown, иначе Алиса/панель потеряют сеть.
- MaxWave предупреждает: установка APK и root — на свой риск; полного отката прошивки нет. Мы не трогаем прошивку и root.
